### `chore: scaffold monorepo, compose stack and tooling`

npm workspaces (`packages/*`, `apps/*`), strict TypeScript, Prettier, Vitest.

`docker-compose.yml` gains a third service: **moto**, the mock AWS control
plane. Both moto environment variables carry comments explaining why they are
required — one of them (`MOTO_ACCOUNT_ID`) prevents a silent failure mode
documented in engineering log #2.

`.env.example` grew an `AWS_MODE` switch (`mock` | `real`) and an Anthropic
section. The AWS onboarding variables are deliberately unchanged in shape from

and real runs.

they already have.

### `feat(shared): domain model for resources, scans and agent traces`

The type definitions every other package imports: `Resource`, `Relationship`,
`ScanRun`, `ScanUnit`, and the agent wire types.

Two pieces of design live here rather than in an implementation:

- **`DerivedFacts`** — `isPublic`, `isAdmin`, `isIdle`, each paired with a
  `reason` string. These are computed by code during ingest, never by the
  model. See ADR-004.
- **`ScanUnit`** — one `(service, region)` pair, carrying its own status and
  error. Making the unit of failure explicit in the *type* is what forces
  partial-failure handling to be designed in rather than bolted on.

`rollUpStatus` derives an overall scan status from the units, so `partial` is a
computed fact rather than something a code path remembers to set.

### `feat(mock-aws): seed a deliberately non-obvious customer account`

A three-region fictional estate built through the real AWS SDK against moto.

The brief asks for mock data whose questions have non-obvious answers, so every
element is chosen to defeat a naive lookup:

- `northwind-public-assets` is public via bucket policy.
  `northwind-reports` has an **identical** wildcard policy that is neutralised
  by `RestrictPublicBuckets`. Reading the policy alone gives the wrong answer
  for one of them.
- `northwind-prod-db` is `PubliclyAccessible: false` in a private subnet, and
  is nonetheless reachable from the internet by **two** different security
  group chains (a three-hop path through the web and app tiers, and a two-hop
  path through a bastion with SSH open to the world).
- `analytics-db` is `PubliclyAccessible: true` and reachable by nobody,
  because its security group opens no ports. The obvious answer is wrong.
- Three roles are effectively administrator. One carries the managed
  `AdministratorAccess` policy, one grants `*:*` **inline** under an innocuous
  name, and one is privileged but entirely unused.

`topology.ts` also carries `GROUND_TRUTH`: the answer key, written by hand from
the topology rather than generated by the code that builds the graph — so a bug
in an analyser cannot grade itself as correct.

Subnets are public because their route table sends `0.0.0.0/0` to an internet
gateway, not because of a tag. The seeder models it that way because the
scanner derives it that way.
